# IntelliBridge 可靠性与超时设计

**状态：已获用户确认**

## 目标

降低 MCP 调用因同步阻塞、连接池无限等待、Hive 连接共享、缓存刷新竞争和长任务无界执行导致的超时与错误，并补齐对应的测试、文档和依赖可复现性。

本轮明确不处理：

- `docker-compose.yml` 的启动入口问题。
- FineCPT source/target 方向过滤问题。

## 设计

### Hive 查询资源管理

Hive 使用“有界并发租约 + 查询独占连接”模型：进程内最多同时运行两个 Hive 查询；请求先等待租约，等待超过配置的队列超时后立即返回；拿到租约后创建独立连接，查询完成后关闭连接并释放租约。应用退出时关闭管理器。

这不是真正的连接池，但符合 Spark 资源最多两个并发的约束，并避免共享 connection/cursor 以及定时重连关闭正在使用的连接。

### 框架级 deadline

增加可复用的 timeout 装饰器和 ASGI 请求超时层。装饰器为 async 调用建立 deadline，并把超时转换为统一异常；请求层将异常映射为明确的 504 响应。同步数据库、浏览器和文件操作放到线程池，底层 HTTP/数据库连接使用当前 deadline 的剩余时间。

Python 线程不能安全地被强制杀死，因此不使用只等待 `Future.result(timeout)` 的伪超时方案。同步任务依靠线程隔离、独立连接、底层 I/O timeout 和有界并发共同收敛。

### MySQL 连接池与调用日志

MySQL pool 在 DBUtils 之外增加有界 slot 控制，连接获取超过配置等待时间时抛出明确超时。节点初始化失败会保留不可用状态而不是被误报为健康。

调用日志改为有界队列和固定后台 worker；队列满时丢弃日志并告警，日志写入不阻塞业务请求，也不为每次调用创建线程。应用退出时停止 worker 并关闭连接池。

### 缓存

DataFactory 和 FineCPT 构建完整的新缓存快照，构建完成后一次性替换旧快照。查询只读取稳定快照，首次加载和定时刷新使用单飞控制，避免在请求中读到半成品字典。

### 查询限制与功能修正

- Hive/MySQL 对最终 SQL 强制施加服务端最大返回行数，不能被用户自带的大 `LIMIT` 绕过。
- Hive `REFRESH` 不追加 `LIMIT`。
- 修复 DataFactory 模糊匹配条件和分页边界。
- 保持现有接口结构，错误以现有 JSON/MCP 返回风格表达。
