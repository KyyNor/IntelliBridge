通过 IntelliBridge 连接 marimo MCP

模型客户端只连接 http://INTELLIBRIDGE_HOST:49000/mcp/marimo。IntelliBridge 连接独立运行的 marimo，将原生工具、参数结构与结果转发给客户端。IntelliBridge 必须能够访问 marimo，模型客户端无需访问 marimo 的内网地址。

启动 marimo

在 marimo 自己的虚拟环境中启用 MCP，保留 token 鉴权。若 IntelliBridge 与 marimo 分机部署，将监听地址改为可达的内网地址。

marimo edit notebook.py --mcp --host 127.0.0.1 --port 2718

marimo 的上游 MCP 路径是 /mcp/server。若 marimo 在容器中，127.0.0.1 指该容器自身。反向代理部署时，按 marimo 文档配置 Host 校验；421 Invalid Host Header 应在上游部署处处理。

配置 IntelliBridge

修改 config/config.yaml，然后重启 IntelliBridge：

marimo:
  enabled: true
  url: "http://MARIMO_HOST:2718/mcp/server"
  token: "填写上游 marimo token"
  timeout: 600
  • enabled 默认为 false。关闭时不挂载路由，也不连接上游。
  • url 是完整 MCP 地址，只支持 HTTP/HTTPS。不允许把凭据、查询参数或片段放进 URL，token 使用单独字段。
  • token 由 IntelliBridge 通过 Bearer 头发送给 marimo。客户端的 Authorization 不会替代上游 token。上游无鉴权时可留空。
  • timeout 是正数秒，控制 marimo 路径的整次 HTTP 请求期限和上游 MCP 请求等待时间。它覆盖该路径上的 server.request_timeout，不改变其他路由的期限。上游 MCP initialize 的等待期限为 10 秒。

代理在请求到达时连接上游，marimo 暂时不可达不会阻止 IntelliBridge 启动。启用后的路由挂载日志只说明本地路由创建成功，不代表上游已经连通。错误配置会记录字段名并跳过挂载，其他服务继续启动。

配置模型客户端

在支持 Streamable HTTP 的 MCP 客户端中配置以下地址。客户端与 IntelliBridge 之间的鉴权按现有入口配置，上游 marimo token 不需要交给模型客户端。

{
  "mcpServers": {
    "marimo": {
      "url": "http://INTELLIBRIDGE_HOST:49000/mcp/marimo"
    }
  }
}

不同客户端的配置格式不同，以上表示端点关系。若 IntelliBridge 前面还有网关，需要允许流式响应，并同步检查网关和客户端的请求期限。进度通知不会取消绝对期限。

能力边界

代理使用现有 FastMCP，不把 marimo 包装进 IntelliBridge 的 Python 环境。marimo 可独立使用 MCP SDK 2.x，IntelliBridge 保持当前 SDK 1.x 依赖。工具名不加前缀、不改参数，转发结构化结果、工具错误与进度通知。

当前 marimo 原生工具可查询 notebook、运行状态、输出、错误、变量及依赖图。代理不会添加创建、编辑、执行或取消 cell 的工具。实际能力以当前上游的 tools/list 为准。

验证接入

先通过模型客户端连接 IntelliBridge，列出原生工具。调用 get_active_notebooks 时，marimo 的参数结构为 {"args": {}}。没有打开的 notebook 会得到空列表，不代表代理失败。

也可以用仓库脚本验证代理模块和真实 marimo。需要 IntelliBridge 的 Python 环境，以及能够访问上游的网络。上游 token 通过环境变量 MARIMO_TOKEN 提供，脚本不输出 token。

python scripts/verify_marimo_proxy.py \
  --url http://MARIMO_HOST:2718/mcp/server \
  --output /tmp/marimo-proxy-verification.json

该脚本使用与 IntelliBridge 相同的代理路由、生命周期和期限中间件，验证真实 MCP 工具发现与调用，不启动 MySQL/Hive 等其他服务。完整部署还需通过实际的 IntelliBridge 地址和入口网关验证。
