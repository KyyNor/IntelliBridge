# 内网部署指南

本指南适用于在内网环境中构建 IntelliBridge Docker 镜像。

## 前置准备

### 1. 下载 Node.js 二进制包

在有外网访问的机器上，从阿里云镜像下载 Node.js 24：

```bash
# 创建 build 目录
mkdir -p build

# 下载 Node.js 24.1.0
curl -L -o build/node-v24.1.0-linux-x64.tar.xz \
  https://mirrors.aliyun.com/nodejs-release/v24.1.0/node-v24.1.0-linux-x64.tar.xz
```

其他下载源（备用）：
- 清华镜像：https://mirrors.tuna.tsinghua.edu.cn/nodejs-release/
- 淘宝镜像：https://npmmirror.com/mirrors/node/

### 2. 配置内网镜像源

复制配置文件模板：

```bash
cp .build.env.example .build.env
```

编辑 `.build.env` 文件，修改为内网镜像源地址：

```bash
# Python 镜像源（修改为内网 PyPI 地址）
PYTHON_PIP_INDEX_URL=http://内网-pypi-地址/simple

# NPM 镜像源（修改为内网 npm 地址）
NPM_REGISTRY=http://内网-npm-地址
```

### 3. 准备部署包

将以下文件打包传输到内网服务器：

```bash
# 必需文件
- Dockerfile
- docker-compose.yml（如果使用）
- requirements.txt
- .build.env
- build/node-v24.1.0-linux-x64.tar.xz
- config/config.yaml
- tools/ 目录
- utils/ 目录
- main.py
```

可以使用以下命令打包：

```bash
tar -czf intellibridge-deploy.tar.gz \
  Dockerfile \
  requirements.txt \
  .build.env \
  build/node-v24.1.0-linux-x64.tar.xz \
  config/ \
  tools/ \
  utils/ \
  main.py
```

## 内网构建

在内网服务器上解压并构建：

```bash
# 解压部署包
tar -xzf intellibridge-deploy.tar.gz
cd intellibridge

# 读取环境变量
export $(cat .build.env | xargs)

# 构建镜像
docker build \
  --build-arg PYTHON_PIP_INDEX_URL=${PYTHON_PIP_INDEX_URL} \
  --build-arg NPM_REGISTRY=${NPM_REGISTRY} \
  -t intellibridge:latest .
```

## 验证构建

```bash
# 验证 Node.js
docker run --rm intellibridge:latest node --version

# 验证 agent-browser
docker run --rm intellibridge:latest agent-browser --version

# 验证 Python 依赖
docker run --rm intellibridge:latest python -c "import fastapi; import fastmcp"
```

## 镜像大小参考

- 包含 Node.js 24.1.0 + agent-browser
- 镜像大小约 **291 MB**
- 传输时建议使用压缩镜像：`docker save intellibridge:latest | gzip > intellibridge.tar.gz`

## 常见问题

### Q: 如何更换 Node.js 版本？

A: 下载对应版本的 tar.xz 包，修改 Dockerfile 中的文件名。

### Q: 内网没有 npm 镜像怎么办？

A: 可以在有外网的机器上预下载 agent-browser：
```bash
npm pack agent-browser
# 将生成的 tgz 文件在 Dockerfile 中使用 npm install -g agent-browser-*.tgz
```

### Q: build 目录被 .dockerignore 忽略怎么办？

A: .dockerignore 已配置为忽略 build/ 目录但保留 `build/*.tar.xz` 文件。
