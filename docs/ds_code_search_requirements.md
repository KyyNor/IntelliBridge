# DolphinScheduler 代码检索工具需求

## 概述

基于 DolphinScheduler 中实际运行的任务代码，构建类似 grep 的检索工具，用于查找分散在不同项目、工作流中的任务代码。

---

## 数据模型

### 数据源

| 数据库标识符 | 实际数据库名 | 表名 | 说明 |
|-------------|-------------|------|------|
| mysql_137 | data_factory | metadata_ds_table_lineage | DS表级元数据信息 |

> 💡 测试环境使用 `mysql_137`，生产环境如有变化再更新此文档

### 核心字段映射

| 字段 | 类型 | 说明 |
|------|------|------|
| project_name | varchar(200) | 项目名称 |
| process_name | varchar(500) | 工作流名称 |
| process_status | varchar(100) | 工作流状态：0-下线，1-上线 |
| task_name | varchar(500) | 任务名称 |
| task_status | varchar(100) | 任务状态：0-未启用，1-启用 |
| from_database_table | varchar(200) | 来源库表（多个用逗号分隔，已脱敏占位符） |
| to_database_table | varchar(200) | 去向库表（多个用逗号分隔，已脱敏占位符） |
| lineage_type | varchar(100) | 血缘类型：SQL / SHELL_SQL（两者存储的都是解析后的 SQL，仅用于区分来源） |
| sql_code | longtext | SQL代码文本（含占位符如 ${var}, @{变量}）|

> 💡 **数据时效性**：表中数据由定时任务每日解析更新（T+1），非实时同步。仅返回任务的最新版本，不涉及历史版本追溯。

### 任务状态判定

| process_status | task_status | 最终任务状态 |
|----------------|-------------|-------------|
| 1 (上线) | 1 (启用) | **已上线** |
| 1 (上线) | 0 (未启用) | 未上线 |
| 0 (下线) | 1 (启用) | 未上线 |
| 0 (下线) | 0 (未启用) | 未上线 |

即：**process_status=1 且 task_status=1 = 已上线**，其他均为未上线。

## 工具一：datafactory_sql_search

对标 grep 的代码检索工具。

### 功能列表

| # | 功能 | 说明 |
|---|------|------|
| 1 | 正则匹配 | 输入正则表达式，输出匹配到的代码 |
| 2 | 路径过滤 | 通过 code_path 指定搜索范围，支持部分匹配 |
| 3 | 大小写不敏感 | 默认忽略大小写 |
| 4 | 上下文参数 | 支持 `before`、`after` 参数，输出匹配行前后N行 |
| 5 | 状态过滤 | 支持 `code_status` 参数，默认只搜索"已上线"的代码 |
| 6 | 分页 | 返回内容自动分页 |
| 7 | 结果去重 | 默认去除重复匹配 |

### code_path 参数说明

将项目、工作流、任务的层级关系封装为路径格式，对 AI 隐藏内部结构。

| 格式 | 示例 | 含义 |
|-----|------|------|
| `/ds/` | `/ds/` | 搜索全部任务 |
| `/ds/项目名/` | `/ds/ODS/` | 搜索指定项目下的所有任务 |
| `/ds/项目名/工作流名/` | `/ds/ODS/日报工作流/` | 搜索指定项目和工作流下的任务 |
| `/ds/项目名/工作流名/任务名` | `/ds/ODS/日报工作流/用户表同步` | 精确到任务，可用于精确查询 |

> 💡 **匹配规则**：
> - 使用 MySQL `LIKE` 进行模糊匹配（去掉末尾斜杠后 `%关键词%` 匹配）
> - 传入参数时会自动 `trim()` 去除首尾空格
> - 支持部分匹配：如 `/ds/OD/` 可匹配到 `ODS`、`ODSWorkshop` 等项目

### 数据规模参考

| 指标 | 数值 |
|------|------|
| 项目数量 | 约 30 个 |
| 任务节点总数 | 约 5000 个 |
| 单任务平均代码行数 | 几百行 |
| 单任务最大代码行数 | 几千行 |


### 请求参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|-----|------|------|--------|------|
| pattern | string | 是 | - | 正则表达式 |
| code_path | string | 否 | `/ds/` | 路径过滤，支持部分匹配 |
| before | int | 否 | 0 | 匹配行前的行数 |
| after | int | 否 | 0 | 匹配行后的行数 |
| code_status | string | 否 | "已上线" | 状态过滤：已上线/未上线/全部 |
| page | int | 否 | 1 | 页码 |
| page_size | int | 否 | 50 | 每页条数 |

### 返回格式

```json
{
  "matches": [
    {
      "code_path": "xxx",
      "行号": 11,
      "代码片段": "select * from table..."
    }
  ],
  "pagination": {
    "page": 1,
    "page_size": 50,
    "total": 100,
    "total_pages": 2
  }
}
```

## 工具二：datafactory_task_info

任务详情查询工具。

### 功能列表

| # | 功能 | 说明 |
|---|------|------|
| 1 | 路径查询 | 通过 code_path 精确或模糊匹配任务 |
| 2 | 代码切片 | 返回代码前100行作为预览 |
| 3 | 代码行数 | 返回完整代码的总行数 |
| 4 | 表清单提取 | 自动识别输入表和输出表 |

### 请求参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|-----|------|------|--------|------|
| code_path | string | 否 | - | 路径筛选，支持精确或模糊匹配（如 `/ds/*/*/决策`） |
| from_table | string | 否 | - | 输入表名称筛选，支持模糊匹配 |
| to_table | string | 否 | - | 输出表名称筛选，支持模糊匹配 |

> 注：三个参数至少填写一个，支持任意组合筛选（AND 逻辑）。

### 返回格式

```json
[
  {
    "code_path": "/ds/ODS/日报工作流/用户表同步",
    "任务类型": "SQL",
    "代码": "select ... -- 前100行",
    "代码行数": 500,
    "任务状态": "已上线/未上线",
    "输入表清单": ["db.table_a", "db.table_b"],
    "输出表清单": ["db.table_c"]
  }
]
```

> 注：返回中的 `code_path` 即任务的唯一标识，可用于后续关联查询。

### 表清单说明

- **来源**：「直接从数据库字段读取，不做二次解析」
- **输入表**：`from_database_table` 字段，格式如 `db.table1,db.table2`
- **输出表**：`to_database_table` 字段，格式如 `db.table1,db.table2`
- 返回时需拆分逗号为数组格式

## 边界情况处理

| 场景 | 处理方式 |
|------|---------|
| sql_code 为 NULL | 返回空字符串，跳过该记录 |
| from/to_database_table 为 NULL | 返回空数组 |
| 无匹配结果 | 返回空数组，total=0，pagination.total=0 |
| code_path 完全匹配多条 | 返回所有匹配的记录，每条记录带完整 code_path |
| 正则语法正确但匹配不到任何内容 | 返回空结果（不同于语法错误） |
| 正则语法错误 | 返回错误提示，说明原因及具体位置 |
| before/after 超出行数范围 | 只返回实际存在的行数 |
| before/after 同时使用且匹配行相邻 | 允许重叠返回，不做去重（保留完整上下文） |
| 所有筛选参数均未填写 | 返回错误提示"请至少填写一个筛选条件" |
| code_path 参数带有前后空格 | 自动 trim() 后再做匹配 |

## 性能与限制

| 项 | 限制 |
|----|------|
| 单次查询最大返回条数 | 1000 条 |
| 默认每页条数 | 50 条 |
| sql_code 截取长度 | datafactory_sql_search: 仅返回匹配行及其上下文；datafactory_task_info: 返回前100行作为预览 |
| 正则表达式超时 | 5 秒，建议使用带超时控制的正则库 |
| code_path 模糊匹配 | 使用 LIKE 匹配 |

### 实现建议

1. **正则匹配流程**：
   - 第一步：从数据库用 LIKE 预筛选（减少数据传输）
   - 第二步：在内存中用 Python `re` 模块做精确正则匹配
   - 第三步：根据 before/after 参数提取上下文行

2. **安全防护**：
   - pattern 参数仅用于内存正则匹配，不做 SQL 拼接（防注入）
   - 推荐使用 `regex` 库替代 `re`，支持超时控制：`regex.match(..., timeout=5)`

3. **排序逻辑**：
   - 搜索结果默认按 `project_name → process_name → task_name` 字母顺序排列
   - 也可以考虑按匹配位置排序（匹配行号小的在前）
